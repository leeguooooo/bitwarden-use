bitwarden-use 0.2.0

Field updates, masked credential reads, domain selection, and macOS Keychain unlock.

Install

curl -fsSL https://raw.githubusercontent.com/leeguooooo/bitwarden-use/main/install.sh | sh
bwu --version

Includes the CLI, background agent, and bwu alias. The installer requires a valid SHA-256 file before replacing executables. macOS Apple Silicon/Intel and Linux x64/ARM64 binaries are available on GitHub Releases.

Update one field

bwu set ITEM --uri https://example.com --match host --dry-run
bwu set ITEM --uri https://example.com --match host --yes
bwu set ITEM --uri-add https://login.example.com --match exact --yes
bwu set ITEM --uri-remove https://login.example.com --yes
bwu set ITEM --totp 'otpauth://totp/example?secret=YOUR_SEED' --yes
bwu set ITEM --field 'Recovery codes=YOUR_VALUE' --yes

--uri replaces the URI list; --uri-add and --uri-remove retain other entries. Modes: base, host, exact, regex, starts-with, never. Base-domain lookup uses the Public Suffix List, including private suffixes.

Writes show a masked preview. Noninteractive calls require --yes; --dry-run never writes. Empty values and removing the final URI require --allow-empty. Unspecified fields, passkeys, attachments, and server metadata are retained. If an edited field changed on the server, sync and review again.

bwu set ITEM --notes '' --allow-empty --yes

Read credentials

bwu get ITEM --json
bwu get ITEM --field password --reveal
bwu get ITEM --field 'custom:Recovery codes' --reveal
bwu get ITEM --codes --reveal
bwu login --domain example.com
bwu login --domain example.com --name ITEM --user USER --reveal

get and domain lookup mask values by default. Add --reveal only when passing credentials directly to their consumer. --raw is an alias-compatible JSON option. Custom fields use exact names; custom: selects a custom field whose name overlaps a built-in name.

Domain lookup returns credentials only for a unique matching login. On zero or multiple matches, stdout is empty and stderr lists masked candidates with stable IDs. Name and user filters are exact; --name also accepts an item UUID. Match modes operate on the supplied URL; an exact path match requires the full URL.

--codes extracts code-shaped standalone lines from notes, optionally numbered or bulleted. It does not validate recovery codes or parse arbitrary prose. Check the source format before using a code. JSON exports and revealed output can include notes and password history; keep them out of logs.

macOS login Keychain

bwu login
bwu unlock --keychain-store
bwu lock
bwu unlock --keychain

Enroll once using pinentry. The password is verified against the local vault before it is saved through the native Keychain API. Later explicit keychain unlocks use the stored value without a pinentry prompt. macOS may still request permission when an application first accesses the item or after its access policy changes. Keychain access does not bypass the operating system or an item's master-password reprompt.

Entries are scoped to profile, server and email under service bitwarden-use.master-password. A changed master password requires re-enrollment. Remove the corresponding entry in Keychain Access to revoke storage. No password is passed through command arguments or written to plaintext configuration.
